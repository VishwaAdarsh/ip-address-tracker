## Detailed Capture Guidelines

### 1. `01_dashboard_landing.png` — Main Console Landing State
- **View:** `Dashboard` (initial load before executing any query)
- **Elements to Include:** Top navigation bar (`IP PULSE` branding, tabs, `● SYSTEM ONLINE` badge), central search input with glowing cyan border, placeholder text, and quick-target pills (`google.com`, `cloudflare.com`, `1.1.1.1`).
- **Report Placement:** Chapter 4 (Design & Implementation — User Interface Overview).

### 2. `02_target_resolution_loading.png` — Asynchronous Pipeline Trigger
- **View:** `Dashboard` (during active lookup for `google.com`)
- **Elements to Include:** The glowing input field with disabled search button, accompanied by the animated pulsing status message: `Querying DNS resolvers, TLS certificates & geolocation telemetry...`.
- **Report Placement:** Chapter 4 (Asynchronous Service Architecture & Non-Blocking Design).

### 3. `03_summary_intelligence_cards.png` — Core Intelligence Telemetry
- **View:** `Dashboard` (immediately following resolution of `google.com`)
- **Elements to Include:** Top triad of summary cards:
  1. *Target IP Card:* IP address (`142.250.190.46`), IPv4 badge, reverse PTR status.
  2. *Location Card:* City (`Mountain View`), Region (`California`), Country (`United States`), coordinates (`37.4056, -122.0775`).
  3. *Network Card:* ASN (`AS15169`), Organization (`Google LLC`), ISP type.
- **Report Placement:** Chapter 4 (Network Telemetry & IP Normalization Layer).

### 4. `04_interactive_leaflet_map.png` — Interactive Geolocation Visualization
- **View:** `Dashboard` (scrolled to map view section)
- **Elements to Include:** Dark-mode Leaflet OpenStreetMap viewport with glowing cyan marker at target latitude/longitude, zoom controls, and the prominent academic disclaimer notice:  
  `* Location shown reflects public network registry allocations, not real-time GPS device tracking.`
- **Report Placement:** Chapter 4 (Geographic Visualization & Leaflet Integration).

### 5. `05_dns_records_matrix.png` — Multi-Record DNS Dissection
- **View:** `Dashboard` (DNS Records section)
- **Elements to Include:** Full DNS records table showing forward and administrative records: A records, AAAA records, MX mail servers with priority numbers, NS authoritative nameservers, and TXT verification strings.
- **Report Placement:** Chapter 3 & 4 (DNS Resolution Architecture & Protocol Dissection).

### 6. `06_website_security_audit.png` — TLS Handshake & Header Compliance
- **View:** `Dashboard` (Website Security section)
- **Elements to Include:** Left side: TLS certificate badge (`VALID`), protocol version (`TLSv1.3`), cipher suite name, expiration countdown. Right side: 6 defensive HTTP security header badges with green (`PASS`) and red (`MISSING`) chips for HSTS, CSP, X-Frame-Options, and X-Content-Type-Options.
- **Report Placement:** Chapter 4 (Active Website Security Auditing Module).

### 7. `07_trust_risk_gauges.png` — Deterministic Dual-Score Engine

- **Elements to Include:** Dual circular SVG gauges displaying Trust Score (85/100, Emerald) and Risk Score (15/100, Crimson), the mathematical invariant label (`Trust + Risk = 100`), and the 5 weighted factor progress bars detailing exact point deductions.
- **Report Placement:** Chapter 4 (Deterministic Scoring Methodology & Algorithmic Formulation).

### 8. `08_ip_personality_profile.png` — Infrastructure Archetype Profiling

## Capturing Instructions for Students

1. **Start the Platform:** Ensure backend is active via `python app.py` and open `http://127.0.0.1:5000` in Google Chrome, Firefox, or Edge.
2. **Browser Zoom:** Set browser zoom to 100% (`Ctrl + 0`) for crisp 1:1 pixel rendering.
3. **Capture Tool:** Use Windows Snipping Tool (`Win + Shift + S`) or browser full-page screenshot (`Ctrl + Shift + I` $\rightarrow$ `Ctrl + Shift + P` $\rightarrow$ "Capture screenshot").
4. **Save Format:** Save directly as PNG files inside `docs/screenshots/` following the naming convention listed in the table above.
